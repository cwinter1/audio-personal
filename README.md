# AI Daily Brief — Personal Audio Archive

Public mirror of audio episodes generated by [`news`](https://github.com/cwinter1/news)
(the AI Daily Brief pipeline), reorganized for RSS playback in a real podcast app
instead of manually downloading files from private GitHub issues.

## Subscribe

Apple Podcasts (iPhone): **Library → Edit (top right) → Add a Show by URL...**, then paste:

```
https://raw.githubusercontent.com/cwinter1/audio-personal/main/feed.xml
```

Episodes play oldest-first by default (`itunes:type: serial`), across all three
sources — daily rotation, FDE (BFSI) track, and on-demand — combined into one
chronological order.

## Structure

- `audio/` — MP3 files, named `<source>_<date>_<topic-slug>.mp3`
  (`source` is `daily`, `fde`, or `ondemand`)
- `manifest.json` — one entry per episode: filename, source, date, title.
  This is the source of truth `scripts/generate_feed.py` reads from.
- `feed.xml` — generated RSS feed. Regenerated automatically by
  `.github/workflows/generate-feed.yml` whenever `manifest.json` or `audio/`
  changes, and can be regenerated manually with `python3 scripts/generate_feed.py`.

## What's not here

17 early FDE episodes (2026-08-26 through 2026-09-13) were deliberately excluded —
the FDE rotation was stuck looping only 2 topics during that window before a real
fix landed upstream in `news` (decision #78), so those files are near-duplicates
of episodes that are included. See `news`'s `CLAUDE.md` decision log for the
full history if you want the excluded issue numbers.

## Adding new episodes

Going forward, `news`'s daily-brief.yml / daily-brief-fde.yml / on-demand-brief-core.yml
workflows push new episodes here directly after each run (see that repo's
Key Files table for the commit step). To add one manually: drop the MP3 in
`audio/`, add its entry to `manifest.json`, push — the workflow above
regenerates `feed.xml` for you.
